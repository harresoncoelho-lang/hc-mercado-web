# scripts — Robôs de coleta e digest (roda via GitHub Actions cron)

Coletores e enriquecedores que alimentam `data/*.json` e o Supabase, mais o digest diário por email. Nenhum roda no request de um usuário — todos são disparados por `.github/workflows/*.yml` em horário fixo (UTC).

## Responsibility

Buscar dados em APIs externas (PNCP, Portal da Transparência), normalizar, mesclar com o histórico já persistido e gravar em `data/*.json` (git) ou no Supabase (`contratos`, `mercado_atas`, tabela genérica `dados_robo`). Não serve requisições HTTP de usuário — isso é `netlify/functions/`. Não decide o que o front-end mostra — `painel.html` é quem consome esses dados prontos.

## Key patterns

- Todo parâmetro operacional vem de `process.env.X` com fallback padrão documentado no cabeçalho do arquivo (`RETENCAO_DIAS`, `LIMITE_MINUTOS_CONTRATOS`, `CONCORRENCIA_PAGINAS`, etc.) — nunca hardcode um desses valores.
- Robôs longos são time-boxed: cronômetro (`inicioExecucao = Date.now()`) + função `tempoRestanteMs()`/orçamento em minutos (`LIMITE_MINUTOS*`) para parar antes do timeout do runner, não um `for` sem limite.
- Coleta é **incremental**: lê o JSON/estado já existente, busca só o delta com uma folga de `FOLGA_DIAS` para publicações atrasadas, mescla e descarta duplicatas/registros mais velhos que `RETENCAO_DIAS`. Nunca reescreva um robô para re-varrer tudo do zero sem essa mesclagem.
- Escrita no Supabase passa por `scripts/supabase_dados.js` (`restFetch`/`upsertEmLotes`/`buscarBlob`/`salvarBlob`), que injeta `SUPABASE_SERVICE_ROLE_KEY` — nunca chame a REST API do Supabase direto de outro robô.
- `chaveServico()` em `supabase_dados.js` lança erro descritivo (com o caminho de configuração no GitHub Actions) se a env var estiver ausente — siga esse padrão de erro acionável em vez de um `throw` genérico.
- `SEGMENTOS`/listas de UF/palavras-chave ficam como constantes nomeadas no topo do arquivo, não espalhadas pelo código.

## Applied rules

- @.claude/rules/javascript.md — módulos CommonJS (`require`/`module.exports`, não ESM) nos robôs `.js`; os robôs `.py` (`boletim_editais.py`) não são cobertos por essa regra.

## Local conventions

- Comentário de cabeçalho obrigatório em todo robô: o que faz, comando de uso (`node scripts/x.js`), e a lista de env vars obrigatórias/opcionais com seus defaults — copie esse formato ao criar um robô novo.
- Robô que grava em `data/*.json` versionado: nunca deixe o arquivo crescer sem poda — sempre aplique a retenção (`RETENCAO_DIAS`) antes de escrever, já que cada commit nesses arquivos dispara um redeploy completo no Netlify.
- Dado que muda com frequência mas não deve virar commit diário: use a tabela `dados_robo` (`chave`/`dado jsonb`) via `buscarBlob`/`salvarBlob`, não um novo arquivo em `data/`.
