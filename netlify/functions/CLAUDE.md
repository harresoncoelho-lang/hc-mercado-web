# netlify/functions — Serverless endpoints (Netlify Functions)

Endpoints HTTP servidos como Netlify Functions (`exports.handler = async (event) => {...}`). Dividem-se em proxies públicos sem custo e endpoints pagos/sensíveis que exigem sessão e cota — a distinção é a coisa mais importante a preservar ao adicionar uma função nova aqui.

## Responsibility

Roteamento HTTP + auth/CORS/quota para chamadas vindas do front-end (`painel.html`) que não podem rodar direto no navegador (custam dinheiro, exigem chave secreta, ou o alvo bloqueia CORS). Lógica de negócio pesada (parsing de PDF, extração via LLM) mora aqui mesmo, dentro do handler — não há camada de service separada. Coleta em lote/agendada (robôs cron) **não** mora aqui — isso é `scripts/`. Consultas diretas ao Postgres a partir do browser também não passam por aqui — isso é o client Supabase em `supabase-config.js`, usado direto em `painel.html`.

## Key patterns

- Toda function exporta `exports.handler = async (event) => { ... }`; primeira linha é sempre `cabecalhosPadrao(event)` ou um header CORS manual equivalente.
- Endpoint que custa dinheiro ou toca dado sensível: importa `{ cabecalhosPadrao, exigirUsuarioLogado, verificarLimiteDiario } = require("./_auth")` e chama ambos antes de qualquer trabalho real (ver `ia-edital.js:322-330`) — nunca pula a ordem `exigirUsuarioLogado` → `verificarLimiteDiario`.
- Proxy público (`pncp-itens.js`, `pncp-arquivos.js`, `pncp-baixar.js`): sem import de `_auth`, `Access-Control-Allow-Origin: "*"` fixo, sem checagem de sessão — existe só para contornar CORS do PNCP.
- Toda chamada `fetch` ao domínio `pncp.gov.br` manda `User-Agent` de navegador (`USER_AGENT_NAVEGADOR`) — sem isso alguns endpoints do PNCP resetam a conexão (ver comentário em `pncp-proxy.js`).
- Erros de negócio retornam `{ statusCode, headers, body: JSON.stringify({ erro: "..." }) }` — nunca lançam exceção não tratada para fora do handler.
- Requisições externas usam `AbortController` + `setTimeout` explícito (8–15s) — nunca um `fetch` sem timeout.
- `_auth.js` é fail-open quando `SUPABASE_SERVICE_ROLE_KEY` não está configurada (`verificarLimiteDiario` retorna `{ ok: true }`) — é intencional, não um bug a "corrigir" adicionando fail-closed.

## Applied rules

- @.claude/rules/javascript.md — módulos CommonJS (`require`/`module.exports`, não ESM), mantenha handlers pequenos e de propósito único.

## Local conventions

- Modelo de LLM (Groq) sempre lido de `process.env.GROQ_MODEL` com fallback hardcoded no topo do arquivo — nunca hardcode sem fallback nem sem o comentário explicando a cota (ver `ia-edital.js:18-22`).
- Lista de origens permitidas (`ORIGENS_PERMITIDAS`) mora só em `_auth.js`; endpoints sensíveis nunca declaram a própria allowlist.
- Novo endpoint pago/sensível: seguir literalmente o cabeçalho de `ia-edital.js` (headers → OPTIONS → método → `exigirUsuarioLogado` → `verificarLimiteDiario`) antes de qualquer lógica de negócio.
